# Tech Stack and Conventions

## Stack

| Concern | Choice |
|---|---|
| Language / runtime | Java 21 |
| Framework | Spring Boot 3.3.x |
| Build | Maven (one independent Maven project per service) |
| API Gateway | Spring Cloud Gateway |
| Persistence | PostgreSQL 16, one database per service |
| Data access | Spring Data JPA + Flyway for schema |
| Message broker | Apache Kafka 3.7 (Spring for Apache Kafka) |
| API docs | springdoc-openapi (Swagger UI at `/swagger-ui.html`) |
| Testing | JUnit 5, Spring Boot Test, Testcontainers for integration tests |
| Containers | Docker, multi-stage builds |
| Orchestration | Kubernetes (Deployment + Service + ConfigMap + Secret per component) |

Pin dependency versions explicitly. Do not use `latest` for base images.

## Service ports

## Conventions

- REST paths are plural and resource-oriented: `/api/cakes`, `/api/baskets/{customerId}/items`,
  `/api/orders`, `/api/cakes/{cakeId}/ratings`, `/api/notifications/orders/{orderId}`.
- Gateway routes strip nothing: the gateway forwards `/api/**` to the owning service unchanged.
- Money is `BigDecimal` with scale 2, `RoundingMode.HALF_UP`. Never use `double` for prices.
- Identifiers are UUIDs generated by the owning service.
- Every service exposes Spring Boot Actuator health at `/actuator/health` with liveness and
  readiness probe groups enabled.
- All configuration comes from environment variables. No credentials in `application.yml`,
  Dockerfiles, or committed manifests.
- Inter-service calls use a `RestClient` bean with a connect and read timeout configured; no
  retry or circuit breaker layer in this increment.
- Errors use one shared response shape: `{ "code", "message", "timestamp", "path" }`, produced by a
  `@RestControllerAdvice` per service.
- Validate request payloads with Jakarta Bean Validation annotations plus `@Valid`.

## Commands

Run from the service directory unless noted.

```bash
# build a single service
mvn clean package

# run tests
mvn test

# run locally
mvn spring-boot:run

# build all containers and start the full stack (repo root)
docker compose up --build

# stop and remove the local stack
docker compose down -v

# apply Kubernetes manifests (repo root)
kubectl apply -f k8s/
```

Do not start long-running processes (`spring-boot:run`, `docker compose up`, `kubectl port-forward`)
in a blocking shell during automated work. Ask the user to run those.
